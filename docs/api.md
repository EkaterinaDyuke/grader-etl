# API грейдера

Справка по источнику данных: что за сервис, какие параметры принимает и что приходит в ответ. Числа ниже получены запросами к боевому API в ноябре 2026 года.

## Запрос

```
GET https://api.itresume.ru/statistics/
```

| Параметр | Что это | Пример |
|---|---|---|
| `client` | имя клиента, регистр важен | `Skillfactory` |
| `client_key` | ключ клиента; хранится в `.env` | — |
| `start` | начало периода, UTC | `2026-05-01 00:00:00` |
| `end` | конец периода, UTC | `2026-06-01 00:00:00` |

Ответ `200` — JSON-массив записей. Других эндпоинтов у сервиса нет.

## Ответ

Реальная запись из ответа за 30 мая 2026 года:

```json
{
  "lti_user_id": "f9afbfd3fd8d30b98ffc7c6faf897ad5",
  "passback_params": "{'oauth_consumer_key': '', 'lis_result_sourcedid': 'course-v1:SkillFactory+DSPR-2.0+14JULY2021:lms.skillfactory.ru-b6dfd0feb02e43fcaddf80a44d9d0b5d:f9afbfd3fd8d30b98ffc7c6faf897ad5', 'lis_outcome_service_url': 'https://lms.skillfactory.ru/courses/course-v1:SkillFactory+DSPR-2.0+14JULY2021/xblock/block-v1:SkillFactory+DSPR-2.0+14JULY2021+type@lti+block@b6dfd0feb02e43fcaddf80a44d9d0b5d/handler_noauth/grade_handler'}",
  "is_correct": null,
  "attempt_type": "run",
  "created_at": "2026-05-30 08:12:48.055911"
}
```

| Поле | Что внутри |
|---|---|
| `lti_user_id` | хеш пользователя, 32 символа из `0-9a-f` |
| `passback_params` | строка со словарем внутри: три нужных поля |
| `is_correct` | `0`, `1` или `null` |
| `attempt_type` | `run` или `submit` |
| `created_at` | время попытки в UTC, строка `ГГГГ-ММ-ДД ЧЧ:ММ:СС.микросекунды` |

## passback_params

Строка выглядит как словарь Python, но это не JSON: одинарные кавычки, `None` вместо `null`. Поэтому разбирается через `ast.literal_eval`, а не `json.loads`.

Внутри три поля:

| Поле | Что означает |
|---|---|
| `oauth_consumer_key` | токен клиента; на практике всегда пустая строка |
| `lis_result_sourcedid` | идентификатор блока с задачей в LMS |
| `lis_outcome_service_url` | адрес, куда отправляется оценка |

Первые два поля есть почти всегда, третье встречается не у всех записей.

## Поведение

- Один запрос — одно окно по времени. Пагинации нет: все записи окна приходят одним ответом.
- Скорость: около 22 секунд фиксированной задержки на запрос плюс примерно 1 200 записей в секунду (замерено на окнах 7 и 30 дней).
- Объем зависит от периода: в 2023 году до 10 тысяч записей за сутки, в 2026-м — около 500.
- Данные есть с октября 2022 по сентябрь 2026 (на момент проверки). Более ранние даты возвращают пустой массив, а не ошибку.

## Ловушки в данных

Найдены на реальных выборках, все учтены в проверках:

- `oauth_consumer_key` всегда пустая строка — проверять «заполнено» нельзя.
- Около 4 записей в сутки приходят без `lti_user_id` и без `passback_params` — такие пропускаются.
- Примерно у 6% записей нет `lis_outcome_service_url` — запись целая, поле остается пустым.
- `is_correct` — число `0` или `1`, а не `true`/`false`; у `run` его нет вовсе.
- `created_at` приходит строкой без отметки пояса — время в UTC, пояс надо проставить самому.

## Ограничения

- Только чтение: изменить данные через API нельзя.
- Ключ клиента передается в адресе запроса, поэтому в логи его не пишем, а в репозитории он только в `.env`.
- Это API поставщика: доступность и скорость зависят от его стороны, своих повторных попыток при ошибке у нас нет.
