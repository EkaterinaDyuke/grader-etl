# Журнал проекта

Пишем сверху вниз, новые записи — сверху. Одна запись = один значимый шаг:
загрузка данных, важное решение, вывод, тупик. Достаточно 3–6 строк.

Смысл: через месяц вы не вспомните, почему выбрали такой способ. Журнал отвечает
на вопросы «что я делала», «зачем», «чем закончилось».

## 2026-11-27 — Google Sheets: агрегаты за день

- **Что сделано:** `src\aggregate.py` — агрегаты по дням (`attempts`, `submits`, `success`,
  `users`, доля успешных); `src\sheets.py` — запись в Google Sheets; оба встроены в `main.py`
  после загрузки. Создан сервисный аккаунт, таблица расшарена на его email, ключ лежит
  в `secrets\google-key.json`, папка в `.gitignore`.
- **Зачем:** закрыть вторую дополнительную задачу — агрегаты должны быть видны без доступа
  к базе.
- **Результат:** 1338 дней в таблице (02.10.2022 — 01.06.2026). Запись 1338 строк занимает
  около 4 секунд, расчет агрегатов по 7 млн строк — около 49 секунд.
- **Решение:** доля успешных считается от **отправок**, а не от всех попыток (у `run` оценки
  нет); Google необязателен — без настроек шаг пропускается с предупреждением; агрегаты
  пересчитываются целиком, чтобы таблица не расходилась с базой.
- **Осталось:** уведомление на почту (следующая запись), затем публичная копия.

## 2026-11-26 — письмо с итогом

- **Что сделано:** `src\notify.py` — письмо через `smtplib` и `ssl`; вызов из `main.py`
  в конце прогона. Настройки SMTP в `.env`, в `.env.example` без личных данных.
- **Зачем:** чтобы об окончании выгрузки узнавали без терминала.
- **Результат:** письмо приходит с периодом, числом окон, вставленными строками, дублями,
  отброшенными записями и временем.
- **Решение:** если почта не настроена — предупреждение в лог и продолжение работы; ошибка
  отправки не прерывает прогон, потому что данные уже в базе.
- **Осталось:** Google Sheets.

## 2026-11-26 — шаг 7: полный прогон

- **Что сделано:** полная выгрузка 01.10.2022 — 01.06.2026 окнами по 14 дней; заполнен раздел
  «Результат» в README; сверено `count(*)` в базе.
- **Зачем:** проверить конвейер на реальном объёме и получить данные для отчётов.
- **Результат:** 96 окон, вставлено 7 066 637, дублей 20 143 (май 2026, загруженный раньше
  при проверке), отброшено 34 700 (0,5%), время 2 ч 3 мин (7 407 секунд). В базе
  **7 086 780 строк** за период 02.10.2022 — 31.05.2026 (23:52 UTC).
- **Решение:** окно 14 дней подтвердилось замером: 96 запросов вместо 1 340. Полный прогон
  мирно пережил дубли — они ушли в конфликт, а не в ошибку.
- **Осталось:** две дополнительные задачи (агрегаты в Google Sheets, письмо на почту),
  затем публичная копия в `C:\My projects`.

## 2026-11-26 — шаг 6: конвейер целиком

- **Что сделано:** модули `config`, `logging_setup`, `api_client`, `loader`, `main`;
  схема `schema.sql`; проверка на месяце — май 2026, 5 окон по 7 дней.
- **Зачем:** собрать конвейер до полного прогона, чтобы ошибки нашлись на маленьком объёме.
- **Результат:** 19 009 вставлено, 1 134 дубля, 4 отброшено, 167 с. Логи пишутся в
  `logs\ГГГГ-ММ-ДД.log`, старые удаляются.
- **Решение:** пачки по 10 000 строк, `commit` на пачку; окно 14 дней — по замерам
  (7 дней — 64 с, 30 дней — 270 с); период в `--start`/`--end`, чтобы проверяющий мог
  прогнать короткий отрезок.
- **Осталось:** полный прогон за весь период.

## 2026-11-25 — шаг 5: база, таблица, первая вставка

- **Что сделано:** создана база `grader_stats`; `src\schema.sql` — таблица `grader_attempts`
  (7 полей из инструкции поставщика + `id`, `CHECK` на `attempt_type`, `UNIQUE` на 4 поля);
  `src\db.py` — класс `Database` (singleton, `RealDictCursor`, `select`/`post`/`close`);
  доступ к базе в `.env`; пробная вставка 485 записей из `data\raw\2026-05-30.json`.
- **Зачем:** проверить схему и вставку до написания боевого конвейера.
- **Результат:** первый запуск — 485 вставлено, второй — 0 вставлено, `count(*)` остался
  485. Дублей нет; 4 записи без `user_id` отсеяны проверкой.
- **Решение:** `ON CONFLICT ON CONSTRAINT grader_attempts_unique_attempt DO NOTHING`;
  `commit` один раз на пачку, а не после каждой строки; `created_at` — `timestamptz`,
  время помечается UTC в `transform.py`.
- **Осталось:** лог с ротацией за 3 дня, затем конвейер (`api_client`, `loader`, `main`)
  и полная выгрузка за период.

## 2026-11-25 — шаг 4: разбор и валидация

- **Что сделано:** `src\transform.py` — `parse_passback` и `convert`; прогон 489 записей
  за сутки через проверку (`scratch\check_rules.py`); время помечено как UTC.
- **Зачем:** привести запись API к виду таблицы и отсеять мусор до загрузки в базу.
- **Результат:** 485 прошло, 4 отсеяны (нет `lti_user_id`). Найдено: `oauth_consumer_key`
  пустой во всех 485 записях, у 31 нет `lis_outcome_service_url`, `is_correct` — числа
  0/1, у `run` — `None`.
- **Решение:** 4 пустые записи пропускаем с записью в лог, 31 запись без URL сохраняем
  с `NULL`. Время в UTC — по документации поставщика, косвенно подтверждено распределением
  активности (`scratch\check_timezone.py`, 25–31.05.2026: минимум в 05:00 МСК, скачок
  в 09:00, обеденный провал в 13:00).
- **Осталось:** PostgreSQL — база, таблица, загрузка.

## 2026-11-24 — шаг 3: первый запрос к API

- **Что сделано:** `scratch\probe_api.py` — запрос за сутки (30.05.2026), ответ сохранён
  в `data\raw\2026-05-30.json`.
- **Зачем:** понять формат, объём и поведение API до написания боевого кода.
- **Результат:** `200`, JSON, 489 записей, 273 737 байт за сутки. Оценка на весь период
  (~1 160 дней): ~570 тыс. записей, ~300 МБ.
- **Решение:** качаем окнами по суткам. В логах **не** пишем `r.url` целиком — в нём
  `client_key` открытым текстом.
- **Осталось:** разбор `passback_params`.

## 2026-11-24 — шаг 2: окружение

- **Что сделано:** `uv init --bare`, затем `uv add requests psycopg2-binary python-dotenv`;
  проверка импорта через `uv run python -c`.
- **Зачем:** рабочее окружение, которое не засоряет системный Python и воспроизводится
  у другого человека по `uv sync`.
- **Результат:** `.venv` на CPython 3.14.7, 7 пакетов. `psycopg2-binary 2.9.13` встал
  готовым пакетом, сборки из исходников не было. Импорт трёх библиотек проходит.
- **Решение:** зависимости минимальные — `pandas` не ставим, обработка на чистом Python.
  Понижение `requires-python` до `>=3.11` отложили на шаг 7 (портфель).
- **Осталось:** шаг 3 — первый живой запрос к API, посмотреть реальный объём ответа.

## 2026-11-24 — шаг 1: папка и паспорт

- **Что сделано:** папка проекта скопирована из шаблона `_template`; заполнен паспорт

- **Результат:** структура из 7 папок и 3 файлов; паспорт ~150 строк; в паспорте отмечено,
  что `oauth_consumer_key` в примере ответа **пустой**, а `created_at` приходит в UTC.
- **Решение:** публичная копия пока не создаётся — она появится на шаге 7 в `C:\My projects`;
  копию инструкции поставщика в публичный репозиторий не несём.
- **Осталось:** шаг 2 — окружение `uv` и зависимости (`requests`, `psycopg2-binary`,
  `python-dotenv`).
